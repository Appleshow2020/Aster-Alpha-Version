# Aster 명세 결정 기록
규칙: 원래 프롬프트와 다르게 말한 것은 가장 최근 답변을 우선한다.

## 원래 프롬프트에서 바뀐 규칙 (명세 변경)

| 원래 규칙 | 변경 | 근거 |
|---|---|---|
| `int?` 금지 | `T?` 허용 | 사용자 결정 |
| 포인터 없음 | `T*`, `&`, 단항 `*`, `->`, `sizeof(T)` | D2, D9 |
| `new C()`는 값 | `new`는 `C*` 반환. `Counter* c = new Counter();` | D11, D11a(B) |
| `this` | `self` (`self->value`) | D11c |
| 암시적 형변환 없음 | `T`를 `T?`에 대입하는 것만 예외 | D13 |
| 타입 매개변수 없음 | 제네릭 함수와 클래스 허용, 제약 없음, 호출은 추론 | D6a, D16, D17 |
| 모든 변수는 타입을 쓴다 | 람다의 첫 대입(`f = x => ...;`)만 타입 없이 선언 | D6b |
| 클래스 변수는 값 | 클래스 값은 참조 의미(공유)이며 암시적 nullable | D11e |
| `throw "문자열"`만 | `throw "s" as 이름`, `throw 이름`, `throw 값` | D4, D14, D14a |
| 문자열 표기 | 큰따옴표와 작은따옴표, 이스케이프는 파이썬과 같다 | N2, D15a |
| `catch (Error error)` | `Exception` 등 파이썬 예외 이름 | D4 |
| `typedef struct`만 | `struct Point {...};`도 허용 | Q2.1 |
| 람다 없음 | `x => 식 -> T`, `(T a) => 식 -> T`, `() => 식 -> T` | D1, D6 |
| 단일 import | `import a.b.*;`, `from a.b import *;` | D12a |

### tests/grammar
valid/invalid 예제는 tests/grammar/ 아래 파일이 기준이다 (Tools/check_conformance.py가 검사한다).
이전 목록의 `print(...)`는 파서 단계에서는 유효하다 (이름 해석 오류는 typecheck가 낸다). `Box<int>`도 제네릭 허용으로 유효하다.

## 파서 단계에서 정한 사항
| 항목 | 결정 |
|---|---|
| 범위 for의 두 변수 이름 | 파서가 검사한다 (AST에 이름이 하나만 남기 때문) |
| 구조체 생성자 이름 | 태그 또는 typedef 별칭. 파서가 파일을 먼저 훑어 별칭을 안다 |
| 빈 문장 `;`, 맨 블록 `{}`, 정의 뒤 `};`, 끝 쉼표 | 문법상 오류 |
| 최상위 `return`, 최상위 `break` | 파서는 통과시킨다 (typecheck가 검사) |
| 선언 대 식 | `a * b;`는 C처럼 포인터 선언, `x < y;`는 식 문장 |
| `;` 누락 오류 | 다음 줄에서 발견되면 앞 줄 끝을 가리킨다 |

## 의미 분석 규칙
- `new C(...)`의 타입은 `C*`. `C* p`는 `p->f()`, 값 `C c`는 `c.f()`. 반대로 쓰면 오류. `self`의 타입은 `C*`.
- 클래스 값은 같은 객체를 가리킨다 (`b = a` 후 `b.value`는 `a.value`). null인 값에 접근하면 런타임 오류.
- 구조체 값은 대입 시 필드를 복사한다 (가정).
- `T`를 `T?`에 대입 가능, 반대는 불가.
- 'NAME = 람다식;' 에서 NAME이 선언 전이면 변수 선언이다. 그 외의 선언 안 된 이름 대입은 오류.
- 제네릭 호출의 T는 인자로 추론한다. 추론할 수 없으면 오류.
- `memset`은 내장 `fn memset<T>(T* ptr, int value, int n) -> T*`. 포인터/str 필드에 0이 아닌 바이트나
  n이 구조체 크기를 넘으면 런타임 오류.
- `null?`, `null*`, `T?*`는 거부. range for의 두 변수 이름은 같아야 한다. setter 매개변수는 `value`.
